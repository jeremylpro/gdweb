# Camera Management & Screen Adaptation

The camera system in `gdweb` handles the translation of the player's world coordinates into screen space, manages transitions between gameplay modes (Cube vs. Ship), and ensures the game remains visually consistent across different browser window dimensions.

## Camera Movement & Following Logic

The camera primarily follows the player on the X-axis at a fixed offset, while the Y-axis movement is constrained by gameplay-specific bounds to simulate the feel of the original Geometry Dash.

### Horizontal Following

The camera's X position is driven by `PLAYER_GAME_CAMERA_X`[src/constants.js9](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L9-L9) In `GameScene`, the camera position is updated relative to the player's progress. The `_cameraXRef` object [src/scenes/GameScene.js36-41](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L36-L41) provides a reactive reference used by the `LevelClass` to handle object culling and parallax.

### Vertical Following (`_updateCameraY`)

The `_updateCameraY` function calculates the camera's vertical position based on the player's state and the current gameplay mode.

- **Cube Mode**: The camera remains relatively static, anchored near the ground.
- **Ship Mode**: The camera introduces a vertical offset (`SHIP_CAMERA_Y_OFFSET`) [src/constants.js6](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L6-L6) to give the player more visibility of the flight path.
- **Bounds**: The system uses `GROUND_BOUNDS_Y`[src/constants.js33](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L33-L33) as the baseline for coordinate transforms.

### End Portal Transition (`_endCamTween`)

When the player enters the end portal, the camera transitions from its active following state to a fixed cinematic position. This is handled by `_endCamTween`[src/scenes/GameScene.js1015-1033](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L1015-L1033) which tweens the camera's Y position to `_endPortalGameY` (default 240) [src/scenes/GameScene.js93](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L93-L93) This ensures the player is centered during the final level-complete animation.

## Screen Adaptation & Resizing

The game dynamically adjusts its internal resolution and scaling factors when the browser window is resized or toggled into fullscreen mode.

### Aspect Ratio Recalculation (`_applyScreenResize`)

The `_applyScreenResize` function is responsible for syncing the Phaser renderer with the window dimensions.

1. It calculates the new width while maintaining a fixed height (`SCREEN_HEIGHT = 640`) [src/constants.js4](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L4-L4)
2. It calls `setScreenWidth(newWidth)`[src/constants.js12-15](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L12-L15) to update the global `SCREEN_WIDTH` and the player's horizontal screen anchor `PLAYER_GAME_CAMERA_X`.
3. It updates the `LevelClass` and `Background` to ensure tiles and parallax layers fill the new width.

### Fullscreen Management

Fullscreen is toggled via `_toggleFullscreen`[src/scenes/GameScene.js153](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L153-L153) The UI updates the texture of the fullscreen button between `toggleFullscreenOn_001.png` and `toggleFullscreenOff_001.png` based on the `this.scale.isFullscreen` state [src/scenes/GameScene.js145-154](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L145-L154)

## Coordinate Systems

The game uses two primary coordinate systems: **World Space** and **Screen Space**.

- **World Space**: Used for physics and level data. The Y-coordinate increases as objects go "up".
- **Screen Space**: Used for rendering in Phaser. The Y-coordinate increases as objects go "down".

The function `worldYToScreenY(worldY)`[src/constants.js36-38](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L36-L38) performs this transformation by subtracting the world Y from the `GROUND_BOUNDS_Y` constant.
