# Global Constants & Coordinate System
Relevant source files
- [src/constants.js](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js)

This page documents the core mathematical and logical foundations of the `gdweb` engine. Central to the project's deterministic physics and visual consistency is `src/constants.js`, which defines the physics timestep, the coordinate transformation logic, and the enumeration of object types used across the player and level systems.

## Physics Constants & Timestep

The engine utilizes a high-frequency fixed timestep to ensure deterministic behavior across different hardware and frame rates. This is critical for a rhythm-based platformer where sub-pixel precision determines whether a player survives a collision.

| Constant | Value | Description |
| --- | --- | --- |
| `TICK_DELTA` | `1 / 240` | The fixed physics update interval (240Hz). [src/constants.js18](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L18-L18) |
| `TIME_SCALE` | `0.9` | Global multiplier for the simulation speed. [src/constants.js20](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L20-L20) |
| `PLAYER_SPEED` | `11.540004` | Horizontal movement units per tick. [src/constants.js19](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L19-L19) |
| `JUMP_VELOCITY` | `1.916398` | Initial vertical impulse when jumping in Cube mode. [src/constants.js21](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L21-L21) |

## Coordinate System & Screen Dimensions

The game operates on a Cartesian coordinate system where the "World Y" increases upwards, mimicking the original Geometry Dash logic. However, Phaser 3 (and standard web graphics) uses a screen-space coordinate system where Y increases downwards.

### World-to-Screen Transformation

The `worldYToScreenY` function acts as the bridge between physics logic and rendering.

- **`GROUND_BOUNDS_Y` (460)**: Represents the visual Y-coordinate of the ground plane on the screen. [src/constants.js33](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L33-L33)
- **Transformation**: `return GROUND_BOUNDS_Y - worldY`. [src/constants.js36-38](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L36-L38)

### Screen Metrics

- **`SCREEN_HEIGHT`**: Fixed at `640` pixels. [src/constants.js4](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L4-L4)
- **`SCREEN_WIDTH`**: Defaults to approximately `1138` pixels (`10240 / 9`), but can be updated dynamically via `setScreenWidth`. [src/constants.js3](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L3-L3)[src/constants.js12-15](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L12-L15)
- **`PLAYER_GAME_CAMERA_X`**: The horizontal anchor point where the player sprite is locked relative to the screen (typically 150 pixels left of center). [src/constants.js9](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L9-L9)[src/constants.js14](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L14-L14)

## Object Type Enumerations

The engine uses two sets of string-based enumerations to identify game objects. These are used by the `LevelLoader` to determine hitboxes and by the `PlayerClass` to handle collision logic.

### Primary Object Types

These are used for core gameplay interactions:

- `OBJECT_TYPE_SOLID`: Walls and floors. [src/constants.js28](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L28-L28)
- `OBJECT_TYPE_HAZARD`: Spikes and deadly obstacles. [src/constants.js29](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L29-L29)
- `OBJECT_TYPE_PORTAL_SHIP`: Triggers transition to Ship mode. [src/constants.js30](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L30-L30)
- `OBJECT_TYPE_PORTAL_CUBE`: Triggers transition back to Cube mode. [src/constants.js31](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L31-L31)

### Secondary Object Types (Level Data)

A more granular set of constants (`OBJECT_TYPE2_*`) is used during level parsing to categorize objects from the level data string:

- `OBJECT_TYPE2_DECORATIVE`: Non-colliding visual elements. [src/constants.js54](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L54-L54)
- `OBJECT_TYPE2_PAD` / `OBJECT_TYPE2_RING`: Jump boosters. [src/constants.js56-57](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L56-L57)
- `OBJECT_TYPE2_TRIGGER`: Color or state changes. [src/constants.js58](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L58-L58)

## Mode-Specific Constants

The transition between Cube and Ship modes changes how the camera and boundaries behave.

- **`SHIP_CAMERA_Y_OFFSET` (180)**: Adjusts the camera verticality when the player enters Ship mode to provide better visibility of the flight path. [src/constants.js6](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L6-L6)
- **`FLY_CEILING` (600)**: Defines the upper boundary limit (from the bottom of the screen) when the player is in Ship mode. [src/constants.js22](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L22-L22)

## Rendering Constants

The engine exports global blend mode references that are used by the `Level` class and particle emitters to handle visual layering.

- **`BLEND_ADD`**: Maps to `Phaser.BlendModes.ADD`. Used for glowing objects and particles. [src/constants.js40](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L40-L40)
- **`BLEND_NORMAL`**: Maps to `Phaser.BlendModes.NORMAL`. [src/constants.js41](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L41-L41)
- **Setters**: `setBlendModeAdd` and `setBlendModeNormal` allow for runtime modification of these modes if the renderer requires a fallback. [src/constants.js43-48](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L43-L48)
