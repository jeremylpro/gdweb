The physics system in `gdweb` is designed to be deterministic and independent of the user's monitor refresh rate. This is achieved through a sub-stepping architecture that quantizes the time delta provided by Phaser's main loop into fixed-size ticks (240 Hz).

## Deterministic Simulation Strategy

To ensure consistent physics behavior (jump heights, collision detection, and movement speed) across different hardware, the engine decouples the simulation from the rendering frame rate. Instead of passing the raw `delta` from Phaser directly to the physics entities, the `GameScene` buffers the elapsed time and executes the simulation in discrete steps of `TICK_DELTA`.

### Key Components

| Component | Code Entity | Description |
| --- | --- | --- |
| **Tick Delta** | `TICK_DELTA` | The fixed time step for simulation (1/240th of a second). [src/constants.js18](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L18-L18) |
| **Delta Buffer** | `this._deltaBuffer` | Accumulates elapsed time from the render loop until enough time has passed to run a physics tick. [src/scenes/GameScene.js193](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L193-L193) |
| **Quantization** | `_quantizeDelta` | Method that calculates how many physics steps should run in the current frame. [src/scenes/GameScene.js460-466](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L460-L466) |

## Delta Quantization Implementation

The core logic for delta management resides in `GameScene.js`. The `_quantizeDelta` function converts the millisecond delta into a count of ticks, ensuring that even if the frame rate drops, the physics "catches up" by running multiple steps in a single frame.

### The `update` Execution Order

When `GameScene.update` is called, it follows a strict sequence to maintain state consistency:

1. **Delta Buffering**: The incoming `deltaMs` is multiplied by `TIME_SCALE` (0.9) and added to `_deltaBuffer`. [src/scenes/GameScene.js460-463](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L460-L463)
2. **Sub-stepping**: A `while` loop runs as long as `_deltaBuffer` exceeds `TICK_DELTA`. [src/scenes/GameScene.js468](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L468-L468)
3. **Physics Update**: Inside the loop, `_player.update()` and `_level.update()` are called. [src/scenes/GameScene.js469-470](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L469-L470)
4. **Camera & Background**: After the physics steps, the camera position is updated based on the player's new coordinates. [src/scenes/GameScene.js485-490](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L485-L490)

## Slide-in Transition & Menu State

The physics loop behavior changes based on whether the player is in the menu or actively playing.

### Transition Logic

When the game starts, a "slide-in" effect occurs. The player does not immediately begin full physics simulation.

- **Menu State**: `_menuActive` is true; the camera moves at a constant speed `_bgSpeedX`. [src/scenes/GameScene.js99](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L99-L99)[src/scenes/GameScene.js435-440](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L435-L440)
- **Slide-in**: Triggered when the play button is pressed. The `_slideIn` flag is set, and the player character slides into the starting position from the left. [src/scenes/GameScene.js100-101](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/GameScene.js#L100-L101)
- **Gameplay**: Once the slide-in completes, the physics loop takes over, and `PLAYER_SPEED` (11.54) becomes the primary driver for `_cameraX`. [src/constants.js19](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L19-L19)
