The **Boot Scene** is the initial stage of the `gdweb` lifecycle, responsible for preparing the WebGL context, loading all required binary and visual assets, and initializing global font caches. It serves as a bridge between the raw engine configuration and the active gameplay environment.

## 1. Scene Lifecycle

The `BootScene` follows the standard Phaser 3 lifecycle, utilizing `preload()` for asset queuing and `create()` for data processing and scene transition.

### Preload Phase

During `preload()`, the scene performs three primary tasks:

1. **WebGL Blend Mode Initialization**: It defines custom blend modes for additive and normal transparency, which are used throughout the game for glow effects and particles [src/scenes/BootScene.js15-21](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/BootScene.js#L15-L21)
2. **Loading UI**: A green progress bar is rendered in the center of the screen, updating its `scaleX` property based on the `load.on("progress")` event [src/scenes/BootScene.js23-33](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/BootScene.js#L23-L33)
3. **Asset Queuing**: All game assets (textures, fonts, audio, and level data) are added to the loader queue [src/scenes/BootScene.js37-56](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/BootScene.js#L37-L56)

### Create Phase

Once all assets are loaded, the `create()` method:

1. Retrieves raw `.fnt` text data from the cache [src/scenes/BootScene.js63-65](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/BootScene.js#L63-L65)
2. Invokes `parseBMFont` to register `bigFont` and `goldFont` into the Phaser bitmap font cache [src/scenes/BootScene.js64-66](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/BootScene.js#L64-L66)
3. Transitions immediately to the `GameScene`[src/scenes/BootScene.js69](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/BootScene.js#L69-L69)

## 3. Bitmap Font Integration

Because the game uses custom AngelCode BMFont files, `src/systems/BitmapFontParser.js` is used to manually register glyphs into the Phaser texture system.

### `parseBMFont` Implementation

The parser iterates through the `.fnt` string, extracting attributes for `info`, `common`, `char`, and `kerning` tags [src/systems/BitmapFontParser.js22-35](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L22-L35) For every character:

- **UV Mapping**: It calculates normalized UV coordinates based on the texture width/height [src/systems/BitmapFontParser.js48-51](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L48-L51)
- **Frame Registration**: It calls `texture.add()` to create a frame for the specific character [src/systems/BitmapFontParser.js72](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L72-L72)
- **Kerning**: Kerning pairs are stored in a two-pass process to ensure proper spacing during rendering [src/systems/BitmapFontParser.js82-85](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L82-L85)

## 5. Audio Context Initialization

The `BootScene` prepares the audio keys, but the actual management is handled by `AudioClass`. During the transition to `GameScene`, the audio system is initialized using the `stereo_madness` key loaded in the boot phase.

- **Music Start**: `AudioClass.startMusic()` adds the sound to the scene with a volume determined by `_effectiveVolume` (0.8 * user volume) [src/systems/AudioManager.js20-28](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/AudioManager.js#L20-L28)
- **Metering**: If enabled, the `_setupAnalyser` function connects the master volume node to a Web Audio `AnalyserNode` to allow for real-time visual scaling of level elements [src/systems/AudioManager.js92-98](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/AudioManager.js#L92-L98)
