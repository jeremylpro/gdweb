The **Bitmap Font Parser** system is responsible for converting AngelCode BMFont specification files (`.fnt`) into a format usable by the Phaser 3 engine. It handles the extraction of character metadata, UV coordinate calculation for texture mapping, and the registration of individual glyphs as frames within a texture.

## Overview

The parser, located in `src/systems/BitmapFontParser.js`, provides a custom implementation for processing bitmap fonts. While Phaser 3 has built-in support for bitmap fonts, this system manually deconstructs the `.fnt` text format to provide fine-grained control over how `bigFont` and `goldFont` (the primary UI fonts for Geometry Dash) are registered in the game's cache [src/systems/BitmapFontParser.js8-92](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L8-L92)

### Integration Flow

The parser is utilized during the `BootScene` lifecycle. After the raw `.png` and `.fnt` files are loaded via the Phaser Loader, `parseBMFont` is called to finalize the assets before the game transitions to `GameScene`[src/scenes/BootScene.js63-66](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/BootScene.js#L63-L66)

## Parsing Implementation

The `parseBMFont(scene, textureKey, rawData)` function processes the text data in two primary passes: a metadata/glyph pass and a kerning pass.

### 1. Metadata and Glyph Processing

The parser iterates through each line of the `.fnt` file, splitting by whitespace and identifying tags [src/systems/BitmapFontParser.js22-26](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L22-L26)

| Tag | Action | Attributes Used |
| --- | --- | --- |
| `info` | Sets base font size | `size` |
| `common` | Sets line height | `lineHeight` |
| `char` | Registers a glyph | `id`, `x`, `y`, `width`, `height`, `xoffset`, `yoffset`, `xadvance` |
| `kerning` | Stores pair data | `first`, `second`, `amount` |

For every `char` tag, the system calculates UV coordinates based on the source texture dimensions [src/systems/BitmapFontParser.js48-51](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L48-L51):

- `u0 = charX / textureWidth`
- `v0 = charY / textureHeight`
- `u1 = (charX + charWidth) / textureWidth`
- `v1 = (charY + charHeight) / textureHeight`

The glyph is then registered as a frame in the Phaser texture using `texture.add(charString, ...)`[src/systems/BitmapFontParser.js71-73](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L71-L73)

### 2. Kerning Two-Pass Logic

Kerning pairs (the adjustment of space between specific letter combinations) are processed in a separate pass to ensure all character definitions exist before they are referenced.

1. **Collection**: During the initial line-by-line loop, kerning data is pushed into a temporary `kerningPairs` array [src/systems/BitmapFontParser.js75-79](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L75-L79)
2. **Assignment**: After the loop, the system iterates through `kerningPairs` and maps the `amount` to the `kerning` object of the `second` character in the pair [src/systems/BitmapFontParser.js82-85](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/systems/BitmapFontParser.js#L82-L85)

## Font Registration in BootScene

The `BootScene` specifically registers two fonts used throughout the UI and game world. These fonts are loaded as a combination of a PNG texture and a FNT descriptor.

| Font Key | Asset Path | Usage |
| --- | --- | --- |
| `bigFont` | `assets/bigFont.png` / `.fnt` | Primary level text, percentage display, large UI headers. |
| `goldFont` | `assets/goldFont.png` / `.fnt` | High scores, statistics, and specialized UI elements. |

The registration occurs in the `create()` method of `BootScene`[src/scenes/BootScene.js58-67](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/scenes/BootScene.js#L58-L67) If the raw text data is successfully retrieved from the cache, `parseBMFont` is invoked with the corresponding texture key.
