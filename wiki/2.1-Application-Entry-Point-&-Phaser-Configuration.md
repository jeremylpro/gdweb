This section provides a technical deep dive into the initialization sequence of the gdweb application. It covers the build-time configuration in `vite.config.js` and the runtime initialization within `src/main.js`, specifically focusing on the Phaser 3 engine settings and the transition between the core scenes.

## Build Configuration (Vite)

The project uses Vite as its build tool and bundler. The configuration is designed to package the entire application into a single, minified Immediately Invoked Function Expression (IIFE) for production deployment.

### Key Build Parameters

- **Entry Point**: The bundler starts at `src/main.js`[vite.config.js11](https://github.com/brokemutt/gdweb/blob/1c1d347a/vite.config.js#L11-L11)
- **Output Format**: It generates an IIFE named `assets/index-game.js`[vite.config.js12-13](https://github.com/brokemutt/gdweb/blob/1c1d347a/vite.config.js#L12-L13)
- **Minification**: Uses `terser` with aggressive settings, including two compression passes and the removal of `console.log` and `debugger` statements [vite.config.js15-21](https://github.com/brokemutt/gdweb/blob/1c1d347a/vite.config.js#L15-L21)
- **Asset Pipeline**: A custom plugin handles the recursive copying of the `assets/` directory and the `index-production.html` file into the `dist/` folder after the bundle is closed [vite.config.js35-51](https://github.com/brokemutt/gdweb/blob/1c1d347a/vite.config.js#L35-L51)

## Phaser Game Configuration

The `phaserConfig` object in `src/main.js` defines the hardware interface and rendering behavior of the engine.

### Hardware and Rendering

| Property | Value | Description |
| --- | --- | --- |
| `type` | `PHASER.AUTO` | Prefers WebGL for hardware acceleration, falling back to Canvas if unavailable [src/main.js21](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L21-L21) |
| `powerPreference` | `"high-performance"` | Hints to the browser to use the discrete GPU on multi-GPU systems [src/main.js34](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L34-L34) |
| `resolution` | `1` | Sets the device pixel ratio [src/main.js24](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L24-L24) |
| `smoothStep` | `true` | Enables FPS smoothing to reduce jitter in the game loop [src/main.js26](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L26-L26) |

### Scaling and Input

The game uses a fixed-height coordinate system (`SCREEN_HEIGHT = 640`) while the width is calculated dynamically [src/constants.js3-4](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L3-L4)

- **Scale Mode**: `PHASER.Scale.FIT` ensures the game maintains its aspect ratio while filling the browser window [src/main.js37](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L37-L37)
- **Centering**: `PHASER.Scale.CENTER_BOTH` centers the canvas within the parent element [src/main.js38](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L38-L38)
- **Input Isolation**: `windowEvents: false` is set to prevent Phaser from capturing input events from the global window object, restricting them to the game canvas [src/main.js31](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L31-L31)

## Application Entry Flow

The application initializes by importing global constants and the two primary scene classes. It then instantiates the `Phaser.Game` object, which triggers the scene lifecycle.

### Domain Lock (Inactive)

`src/main.js` contains a commented-out security block designed to prevent the game from running on unauthorized domains. It uses an array of character codes `[103, 101, 111, ...]` to reconstruct the string `"geometrydash.com"` and checks it against `window.location.hostname`[src/main.js13-17](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L13-L17)

### Scene Array

The `scene` property in the config defines the order of initialization:

1. **`BootScene`**: Handles asset loading, font parsing, and initial state setup [src/main.js40](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L40-L40)
2. **`GameScene`**: The main gameplay loop, including the title screen and physics simulation [src/main.js40](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/main.js#L40-L40)

## Data Flow: Constants to Configuration

The configuration relies on exported values from `src/constants.js`. The initial `SCREEN_WIDTH` is calculated based on a specific ratio (`10240 / 9`), resulting in a default value of approximately 1138 pixels [src/constants.js3](https://github.com/brokemutt/gdweb/blob/1c1d347a/src/constants.js#L3-L3)
